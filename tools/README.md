# Инструменты проекта

Запускать из корня проекта. В командах ниже используется `python3` —
так он называется в Linux/macOS. На Windows команда обычно называется
просто `python`: замените `python3` на `python` в любой команде ниже.

## Проверка данных

```
python3 tools/validate.py
```

Проверяет манифест, структуру блоков, уникальность якорей, перекрёстные
ссылки и синтаксис примеров кода. Для заданий с автопроверкой дополнительно:

* схема `check` — известный режим, непустой `cases`, обязательные поля
  режима (`entry` для `function`, `code` для `asserts`), хотя бы один
  открытый кейс;
* уникальность `id` заданий по всем файлам;
* **прогон эталонного решения против его же тестов.**

Последнее — главная защита от опечатки в `expect`. Без неё ошибка автора
вылезает не у автора, а у ученика, который десять минут ищет проблему
в правильном коде. Решение исполняется отдельным процессом с таймаутом
5 секунд во временном каталоге.

Возвращает код 1 при ошибках — можно вешать на pre-commit и CI.

## Сборка поискового индекса

```
python3 tools/build_search_index.py           # собрать
python3 tools/build_search_index.py --check   # сверить, не записывая
```

Собирает `data/search-index.json`. **Запускать после каждой правки
контента**, иначе поиск будет искать по старым данным. Режим `--check`
возвращает 1, если лежащий в репозитории индекс отстал от контента.

## Сквозной тест интерфейса

```
npm install jsdom      # один раз (или просто npm install — jsdom уже в package.json)
node tools/e2e.mjs
```

Прогоняет навигацию, меню, якоря, поиск, защищённый раздел, дедупликацию
запросов, а также копирование кода, песочницу, автопроверку, сохранение
черновиков при перерисовке и запись прогресса.

Настоящий Pyodide в jsdom не поднимается, поэтому исполнитель подменён
заглушкой: тест проверяет обвязку интерфейса. Питоновскую часть проверяет
`validate.py` на эталонных решениях.

## Пилотные задания

```
python3 tools/seed_tasks.py
```

Разовый скрипт, которым добавлена первая партия заданий с автопроверкой.
Оставлен в репозитории как образец формата: по нему удобно дописывать
следующие партии, не выдумывая структуру заново. Повторный запуск
безопасен — задание с существующим `id` не дублируется.

## Типовой порядок перед коммитом

```
python3 tools/validate.py \
  && python3 tools/build_search_index.py \
  && python3 tools/build_search_index.py --check \
  && node tools/e2e.mjs
```

Та же цепочка (без пересборки индекса — только сверка) одной командой
из корня проекта: `npm test`. Она же гоняется в CI на каждый push и
pull request — см. `.github/workflows/ci.yml`.

## Локальный запуск платформы

Песочница живёт в Web Worker, а он не поднимается по `file://`.
Открывать через http:

```
python3 -m http.server 8000
```

Дальше `http://localhost:8000`. Без сервера справочник работает,
но кнопки «Запустить» и «Проверить» не появятся.
