# Серверный прототип

Опыт, а не замена. Вопрос был простой: станет ли кода меньше и чище,
если страницы собирает сервер, а не JavaScript. Здесь на него отвечают
работающие страницы, а не рассуждения.

Статическая версия в корне репозитория продолжает жить своей жизнью —
прототип ничего в ней не трогает и читает те же `data/*.json`.

## Запуск

```bash
pip install django jinja2
cd server
python manage.py runserver
```

Ни базы, ни миграций, ни `createsuperuser`: контент по-прежнему лежит
в JSON, а прогресс ученика — в `localStorage`. Решение «без ЛК и без
базы» этот прототип не отменяет.

Открывать: `http://127.0.0.1:8000/m/6/list/7/` — седьмой шаг раздела
«Списки». Адрес настоящий, не якорь.

## Что получилось

| | статика | прототип |
|---|---:|---:|
| отрисовка | 1039 строк JS | 411 строк шаблонов |
| маршруты | 192 строки JS | 13 строк `urls.py` |
| контент, нарезка на шаги | — | 145 строк `content.py` |
| песочница, прогресс, викторина | 841 строка JS | 418 строк `interactive.js` |
| **всего** | **2221** | **1167** |

Сравнение честное в обе стороны: прототип не умеет поиск и видеомодули,
а в статике эти 2221 строки включают и то, чего в прототипе пока нет.

## Что видно на коде

**Диспетчер типов блоков исчез.** Был `switch` на двенадцать веток
в `renderNoteBlock`. Стал одной строкой в `templates/section.html`:

```jinja
{% include "blocks/" ~ block.type ~ ".html" %}
```

Новый тип блока — это новый файл, а не правка ветвления.

**Девяносто семь ручных `esc()` не нужны.** Jinja экранирует сама.
В этом проекте на ручном экранировании дважды ловили баги: `highlight()`
резал экранированную строку не по тем позициям и рвал HTML-сущность,
`renderModuleHeader` не экранировал `icon`. Оба невозможны здесь.

**Правило нарезки на шаги стало одним.** В статике оно записано дважды:
`sectionSteps` в `app.js` для отрисовки и `section_steps` на Python для
поискового индекса. `content.py` импортирует второе и первого не заводит —
это закрывает остаток долга Д-5.

## Чего сервер не забрал и не заберёт

**Песочница.** Pyodide работает в браузере ученика. Перенос исполнения
на сервер означал бы изоляцию, лимиты и чужой код на своей машине —
менять нулевую поверхность атаки на эту задачу никто не просил.

**Подсветка кода.** Перерисовывается на каждое нажатие клавиши.

**Прогресс.** Живёт в `localStorage`, сервер про ученика не знает.

Остаток — 418 строк `interactive.js` — это и есть честный ответ на
«половина блоков интерактивна, и что?». Ровно четыре вещи, и ни одна
из них не собирает экран.
