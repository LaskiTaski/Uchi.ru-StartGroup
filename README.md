# Python Academy

Учебная платформа по Python: видеомодули с занятиями, текстовые справочники,
курсы и подборки внешних материалов. Примеры кода можно исполнять прямо
в браузере — песочница на [Pyodide](https://pyodide.org/) работает в Web
Worker, без бэкенда. Часть заданий проверяется автоматически, прогресс
ученика (решённые задания, черновики кода) хранится в `localStorage`.

Статический сайт: vanilla JS без сборки и фреймворков, весь контент —
в JSON. Опубликован на GitHub Pages с ветки `main`:
<https://laskitaski.github.io/Uchi.ru-StartGroup/> — всё, что попадает
в `main`, сразу видят ученики, поэтому изменения идут через ветку и PR.

## Структура репозитория

| Путь | Назначение |
|---|---|
| `index.html` | разметка страницы, точка входа |
| `app.js` | рендер интерфейса: навигация, модули, поиск, блоки справочника |
| `sandbox.js` | UI песочницы (редактор, вывод, кнопки) в главном потоке |
| `worker.js` | Web Worker: поднимает Pyodide, исполняет код и проверки |
| `sandbox_runtime.py` | ядро исполнения — общее для браузера и `tools/validate.py` |
| `styles.css` | вся стилизация |
| `data/` | контент: `manifest.json` + JSON-файлы модулей/справочников/курсов |
| `screenshots/` | изображения для блоков `screenshots` |
| `tools/` | скрипты проверки данных, сборки индекса и e2e-теста (см. `tools/README.md`) |

## Локальный запуск

```
python -m http.server 8000
```

Открыть `http://localhost:8000`. Через `file://` сайт не заработает:
Web Worker и `fetch()` данных из `data/` браузер блокирует для локальных
файлов — нужен настоящий HTTP-сервер, пусть и самый простой.

## Формат данных

### Манифест

`data/manifest.json` описывает навигацию, сам контент лежит в других файлах:

- `groups` — вкладки верхнего уровня (`id`, `icon`, `label`, `color`, …);
- `modules` — карточки внутри групп: `id`, `group`, `file` (путь к JSON
  с контентом), `icon`, `label`, `sub`, `color`, `menu` (показывать в
  выпадающем меню), `protected` (раздел под паролем);
- `search.index` — путь к предсобранному поисковому индексу.

### Видеомодуль (файлы с `lessons`, например `data/module1.json`)

Массив `lessons`, у каждого занятия: `num`, `title`, `desc`, `videos[]`
(`id` — YouTube id, `title`), `links[]` (`url`, `title`), `screenshots[]`
(`src`, `caption`), необязательные `badges[]`. Последним элементом может
идти занятие-аттестация: `{ "title": "...", "attestation": true }` — для
него остальные поля не нужны. Необязательный `extra` — блок дополнительной
информации на весь модуль, тоже со `screenshots[]`.

### Справочник или курс (файлы с `sections`, например `data/notes.json`,
### `data/course1.json`)

`type: "notes"` или `"course"`. У каждого раздела в `sections[]`: `num`,
`anchor` (уникален по всем файлам сразу), `chip`/`chipNote` (плитка
быстрого перехода), `title`, `desc`, `blocks[]`. Необязательно:

- `about` — вводная карточка курса: `text` и `meta[]` (`label` + `value`);
- `roadmap[]` — дорожная карта: `title`, `note`, `anchor` (ведёт на раздел
  этого же файла).

### Карточки внешних курсов (`type: "courses"`, `data/module5.json`)

`sections[].groups[].courses[]`: `name`, `url`, и подписи `price` /
`difficulty` / `value` из ограниченного набора ключей, которым в `app.js`
сопоставлен русский текст (`free`, `paid`, `easy`, `medium`, `hard`,
`heavy`, `useful`, `super`, `start`, `optional`, `unknown`).

### Типы блоков (`section.blocks[]`)

| `type` | Обязательные поля | Что рисует |
|---|---|---|
| `text` | `text` | абзац |
| `heading` | `text` | подзаголовок-разделитель |
| `code` | `code` | блок кода; `title`, `lang`, `run: true` (кнопка «Запустить», только для Python) |
| `table` | `rows` | таблица; `head` — заголовок колонок |
| `compare` | `good` и/или `bad` | две карточки «плохо/хорошо» рядом |
| `good` / `bad` | — | одна такая карточка |
| `note` / `warn` | `text` | врезка-подсказка / предупреждение |
| `task` | `text` | практическое задание (см. ниже) |
| `quiz` | `id`, `questions` | викторина: вопросы с вариантами ответа (см. «Викторины» ниже) |
| `checklist` | `items` | список-чеклист, `title` необязателен |

Мини-разметка внутри `text`/`desc` и похожих полей: `` `код` `` →
моноширинный текст, `**жирный**` → выделение, `[текст](#anchor)` →
переход к разделу справочника по якорю.

## Задания с автопроверкой

Формат — `type: "task"` с полями `id`, `title`, `text`, `starter`
(стартовый код), `check`, `hint`, `solution`, `explain` (разбор под
спойлером). Без `check` блок работает как раньше — просто условие
с необязательным разбором. Образец наполнения — `tools/seed_tasks.py`,
подробности замысла — `plan-dorabotok.md`, раздел «Этап 2».

`check` — три режима:

- **`stdout`** — сравнение вывода программы. `cases[]`: `stdin`, `expect`.
  Необязательный `normalize`: `["collapse-spaces", "case"]` (обрезка
  пробелов по краям строк происходит всегда).
- **`function`** — вызов функции. Нужен `entry` (имя функции), `cases[]`:
  `args[]`, `expect`. Числа сравниваются через `math.isclose`.
- **`asserts`** — произвольный код проверки после кода ученика. `cases[]`:
  `code` (использует `assert`).

У любого кейса — необязательные `hidden: true` (кейс не показывается
целиком, только в сводке) и `note` (подсказка вместо содержимого скрытого
кейса — обязательна, если кейс скрыт). Хотя бы один кейс в задании должен
быть открытым.

`tools/validate.py` прогоняет `solution` каждого задания против его же
`check` и падает, если эталонное решение не проходит собственные тесты —
это единственное, что ловит опечатку в `expect` до того, как её найдёт
ученик.

## Викторины

Формат — `type: "quiz"` с полями `id` (уникален по всем данным, как у
задания), необязательным `title` и `questions[]` (1–10 вопросов). У
каждого вопроса: `text`, `options[]` (2–6 вариантов), `answer` (индекс
верного варианта в `options`) и `explain` (пояснение, показывается
после проверки для каждого вопроса).

Живёт на вкладке «Практика» наравне с `task` и считается в прогрессе
так же: решённой викторина становится, когда все вопросы отвечены
верно, отметка пишется в тот же `PA.store`, что и у задания. Годится
там, где задание с автопроверкой избыточно — вопросы «на узнавание»
вроде «что напечатает программа?», где ученику нужно выбрать ответ,
а не написать код.

## Инструменты и порядок перед коммитом

```
python tools/validate.py
python tools/build_search_index.py
python tools/build_search_index.py --check
node tools/e2e.mjs
```

Или одной командой: `npm test` (обёртка над `validate` → `index:check` →
`e2e`; пересборку индекса командой `npm run index` перед этим нужно
выполнить отдельно, если менялся контент). Подробности каждого шага —
в `tools/README.md`. Тот же набор проверок гоняется в CI на каждый push
и pull request — `.github/workflows/ci.yml`.
