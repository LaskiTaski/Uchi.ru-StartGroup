### Найдено по ходу

- В режиме автопроверки `input()` не должен печатать введённое эхом:
  захваченный вывод не сошёлся бы с `expect` ни в одном задании с вводом.
  Эхо оставлено только в режиме «Запустить», где делает вывод похожим
  на сеанс в терминале. Правка: `_pa_exec(..., echo=False)` при проверке.

Обработчик — в существующую таблицу `CLICK_ROUTES`, `navigator.clipboard.writeText`,
на 1.5 с подмена подписи на «Скопировано».

Копировать нужно **исходный текст**, а не `textContent` подсвеченного `<pre>` —
иначе на длинных примерах можно поймать расхождение по пробелам. Решение:
класть оригинал в `data-code` через `esc()` и брать оттуда.

### 0.2 Состояние переживает перерисовку

Сейчас `loadModule` (app.js:291) делает `content.innerHTML = renderModule(data)`
при каждом переключении модуля. Как только в блоках появятся редакторы, весь
введённый учеником код будет теряться при клике на соседнюю вкладку.

Нужен реестр состояния — `Map` вида `blockKey -> { code, stdin }`, где
`blockKey = anchor + ':' + blockIndex`. Перед перерисовкой снимаем состояние
со всех живых редакторов, после — восстанавливаем. Дублируем в `localStorage`
с дебаунсом 1 с, чтобы код переживал перезагрузку страницы.

Чтобы ключ был стабильным, каждому блоку при рендере проставляем
`data-block-key`. Индекс блока внутри раздела как часть ключа означает,
что вставка блока в середину раздела сбивает привязку — приемлемо, но
в заданиях лучше задавать явный `"id"` в JSON и валидировать его уникальность.

## Этап 1. Песочница: запуск Python в браузере

### 1.1 Выбор движка

**Pyodide** (CPython в WebAssembly). Альтернативы — Skulpt (быстрее грузится,
но неполный Python 3, ломается на f-строках и части stdlib) и серверный
исполнитель (нужен бэкенд, изоляция, квоты — для статической платформы
избыточно). Pyodide даёт настоящий CPython, тот же `random`, `math`,
`datetime`, `json`, `decimal` — то есть весь `notes6.json` заработает как есть.

Цена: ~10 МБ на первую загрузку. Поэтому — **ленивая инициализация**: движок
грузится при первом клике на «Запустить», с индикатором и текстом
«Готовим Python, ~10 МБ, только в первый раз». Дальше кешируется браузером.

### 1.2 Обязательно — Web Worker

Pyodide на главном потоке нельзя остановить: любой `while True:` в ученическом
коде намертво вешает вкладку, и единственный выход — закрыть её вместе со всем
введённым текстом. В курсе есть раздел «Цикл while» — бесконечные циклы там
не случайность, а нормальная ошибка обучения.

Поэтому: Pyodide живёт в `worker.js`, главный поток общается с ним сообщениями.
Таймаут 5 секунд, по истечении — `worker.terminate()`, сообщение
«Программа выполнялась слишком долго. Возможно, цикл не заканчивается»,
и подъём нового воркера в фоне.

Протокол сообщений:

```
→ { type: 'run',   id, code, stdin }
← { type: 'ready' }
← { type: 'out',   id, stream: 'stdout'|'stderr', text }
← { type: 'done',  id, ok: true }
← { type: 'error', id, message, line }
```

Вывод стримить порциями, а не отдавать одним куском в конце: длинные циклы
с `print` должны показывать вывод по мере работы.

### 1.3 Поддержка `input()`

Критично для этой платформы: `input()` появляется уже в уроке 1.2 и дальше
идёт сквозь весь материал.

В воркере нет `prompt()`, а синхронный ввод в WASM требует SharedArrayBuffer
и заголовков COOP/COEP на хостинге. Простое решение без серверных заголовков:
**поле «Ввод»** под редактором — многострочный текст, каждая строка отдаётся
как один `input()`. Перед запуском подменяем stdin:

```python
import sys, io
sys.stdin = io.StringIO(stdin_text)
```

Если строки закончились, а код запросил ещё ввод — перехватываем `EOFError`
и показываем «Программа ждёт ввода, но поле «Ввод» пустое (или строк не хватило)»,
что понятнее стандартного трейсбека.

В JSON-блоках предзаполняем поле осмысленным примером через `"stdin"`.

### 1.4 Редактор

Минимальный вариант — `<textarea>` поверх существующей подсветки: при фокусе
показывается textarea, при потере — перерисованный `highlightPy`. Работает,
но без подсветки во время набора.

Рекомендую **CodeMirror 6** (~110 КБ gzip, ленивой загрузкой вместе с Pyodide):
подсветка при наборе, автоотступ после `:`, номера строк, отступ Tab. Для
курса, где отдельный раздел посвящён отступам («Отступы: как Python понимает
структуру»), автоотступ снимает целый класс тупых ошибок.

Обязательно: кнопка «Сбросить» возвращает исходный код примера.

### 1.5 Схема данных

Кнопка появляется не у всех 349 блоков, а по флагу:

```json
{
  "type": "code",
  "code": "n = int(input())\nprint(n * 2)",
  "run": true,
  "stdin": "21",
  "title": "Удвоение числа"
}
```

`"lang"` отличный от `python` кнопку не получает — команды терминала
запускать нечем.

### 1.6 Что не заработает

Стоит написать в интерфейсе честно, одной строкой в подсказке у песочницы:
нет сети (`requests` из `notes6.json` не выполнится), нет файловой системы
проекта (для раздела «Работа с файлами» нужен виртуальный FS Pyodide —
он есть, но файлы живут только до перезагрузки), `pip install` работает
только для пакетов, собранных под Pyodide.

## Этап 2. Автопроверка заданий

### 2.1 Формат задания

Расширяем существующий `task` (app.js:894) полем `check` — старые задания
без него продолжают работать как есть, только с разбором под спойлером.

```json
{
  "type": "task",
  "id": "pal-1",
  "title": "Палиндром",
  "text": "Напишите функцию `is_palindrome(s)`...",
  "starter": "def is_palindrome(s):\n    ",
  "check": {
    "mode": "function",
    "entry": "is_palindrome",
    "cases": [
      { "args": ["шалаш"],  "expect": true },
      { "args": ["привет"], "expect": false },
      { "args": ["А роза упала на лапу Азора"], "expect": true,
        "hidden": true, "note": "пробелы и регистр" }
    ]
  },
  "hint": "...",
  "solution": "...",
  "explain": "..."
}
```

Три режима проверки — их хватает на весь диапазон материала:

- **`stdout`** — сравнение вывода при заданном `stdin`. Для модулей 1–2, где
  всё строится на `print` и `input`, это основной режим.
  Опции нормализации: `"normalize": ["trim", "collapse-spaces", "case"]`.
- **`function`** — вызов функции с аргументами и сравнение результата.
  Для `notes3.json` (Функции) и дальше. Сравнение чисел с плавающей точкой —
  через `math.isclose`, иначе `0.1 + 0.2` будет вечным источником ложных
  провалов.
- **`asserts`** — произвольный python-код проверки, выполняется после кода
  ученика. Запасной вариант для ООП: «создайте класс `Dog` с методом `bark`».

### 2.2 Как исполняется проверка

Тот же воркер, что и песочница. Главный поток собирает harness: код ученика +
проверочная обвязка, которая печатает результат в служебный поток JSON-строкой.

```python
# --- код ученика ---
{user_code}
# --- проверка ---
import json, math
_results = []
for _case in {cases_json}:
    try:
        _got = is_palindrome(*_case["args"])
        _ok = _got == _case["expect"]
    except Exception as _e:
        _got, _ok = f"{type(_e).__name__}: {_e}", False
    _results.append({"ok": _ok, "got": repr(_got), "case": _case})
print("<<<PA_RESULT>>>" + json.dumps(_results, ensure_ascii=False))
```

Два подводных камня:

1. Если ученик забыл `def` или ошибся в имени, harness упадёт с `NameError`
   на строке проверки — и ученик увидит ошибку в коде, которого не писал.
   Ловим отдельно и выдаём: «Не нашли функцию `is_palindrome`. Проверьте имя».
2. Ученический `print` попадёт в общий поток вперемешку с маркером результата.
   Поэтому маркер, а не голый JSON: всё до `<<<PA_RESULT>>>` показываем как
   обычный вывод программы, остальное парсим.

### 2.3 Интерфейс задания

Три кнопки: **Запустить** (просто выполнить, увидеть вывод), **Проверить**
(прогнать тесты), **Показать разбор** (существующий спойлер).

Результат проверки — список кейсов:

```
✅ is_palindrome('шалаш') → True
✅ is_palindrome('привет') → False
❌ скрытый тест: пробелы и регистр
   ожидалось True, получено False
```

Открытые кейсы показываем полностью — ученик должен понимать, на чём упал.
У скрытых показываем только `note`: подсказка есть, готового ответа нет.
Прятать имеет смысл ровно те кейсы, что ломают наивное решение — это
ровно та идея, что уже описана в `course1.json` про каверзные примеры.

Формулировка при провале не должна быть приговором: «Пока не проходит 1 из 3»
вместо «Ошибка».

### 2.4 Валидатор проверяет сами задания

Самое важное для этапа 3 и единственное, что удержит качество на 150+ заданиях:
**`tools/validate.py` прогоняет `solution` против `check` и падает, если
эталонное решение не проходит собственные тесты.**

Иначе опечатка в `expect` вылезет не у автора, а у ученика, который будет
десять минут искать ошибку в правильном коде.

Реализация: `subprocess` с локальным `python3`, таймаут 5 с на задание,
отдельный временный каталог. Плюс проверки: уникальность `id` заданий,
непустой `cases`, наличие хотя бы одного открытого кейса, соответствие
`mode` набору полей (`entry` обязателен для `function`, `stdin` — для `stdout`).

Дополнить `BLOCK_SCHEMA` (validate.py:27) и прогон в `tools/e2e.mjs`:
сценарий «ввести заведомо неверный код → увидеть красный результат →
ввести решение → увидеть зелёный».

## Этап 3. Наполнение заданиями

Сейчас `task` встречается только в `course1.json` — 5 штук. В шести файлах
справочника, где лежит основной материал, заданий нет вообще.

### Норма и объём

2–3 задания на раздел, 72 раздела → 150–200 заданий. Это самая долгая часть
плана и единственная, где нельзя сэкономить инженерией — писать и вычитывать
условия придётся руками.

### Порядок

1. **`notes.json`** (Основы, 14 разделов) и **`notes2.json`** (Ветвление
   и циклы, 8 разделов) — сюда попадает большинство учеников, здесь режим
   `stdout` покрывает почти всё. ~60 заданий.
2. **`notes3.json`** (Функции, 13 разделов) — режим `function`, самый
   удобный для автопроверки. ~35 заданий.
3. **`notes4.json`** (Ошибки) и **`notes6.json`** (Модули и файлы) — ~40.
4. **`notes5.json`** (ООП, 14 разделов) — режим `asserts`, дороже всего
   в написании. ~40.

### Шаблон, чтобы задания были однородными

На каждый раздел: одно на **узнавание** («что напечатает этот код?» —
проверяется `stdout` без ввода кода вообще), одно на **применение**
(написать по образцу из раздела), одно на **перенос** (та же идея в новом
контексте, с каверзным скрытым кейсом).

Задание первого типа стоит почти ничего в написании, а работает лучше всего
на старте — ученику не нужно бороться с синтаксисом, чтобы проверить,
понял ли он материал.

## Этап 4. Прогресс ученика

Появляется естественно из этапа 2: раз задания проверяются, результат надо
где-то держать.

Ключ `pa_progress_v1`:

```json
{
  "version": 1,
  "tasks": { "pal-1": { "status": "solved", "ts": 1756500000, "tries": 3 } },
  "sections": { "types-overview": { "seen": 1756400000 } },
  "drafts": { "pal-1": "def is_palindrome(s):\n    return s == s[::-1]" }
}
```

Что даёт:

- галочки на плитках «Быстрого перехода» (`.qn-chip`) и в оглавлении вкладки;
- полоса «решено 12 из 34» в шапке модуля;
- кнопка «Продолжить» — к первому нерешённому заданию;
- черновики: ученик вернулся через день и код на месте.

Экспорт/импорт прогресса одной JSON-кнопкой: `localStorage` живёт до первой
чистки браузера, а на корпоративных машинах она бывает по расписанию.

Отдельно — учётная запись не нужна: платформа статическая, всё в браузере.
Если позже понадобится видеть прогресс на стороне компании, единственная
точка изменений — модуль хранилища с интерфейсом `get/set/flush`,
за которым вместо `localStorage` окажется вызов API. Заложить этот интерфейс
сразу — стоит полчаса, переписывать потом — день.

## Этап 5. Инфраструктура интерфейса

Не блокирует ничего выше, делается параллельно или после.

**Поиск.** `BODY_LIMIT = 600` в `build_search_index.py` режет тело раздела
до 600 символов — всё, что дальше, не ищется. Поднять до 2000 (индекс вырастет
с 88 КБ примерно до 250 КБ — на фоне 10 МБ Pyodide несущественно) и добавить
простой стемминг: отсечение русских окончаний перед сравнением, чтобы «циклы»
находили «цикл». Плюс индексировать текст заданий.

**Адаптив.** В 40 КБ CSS одна медиа-точка `max-width: 640px`. Диапазон
640–1024 не проработан, а песочница с редактором и полем ввода потребует
отдельной раскладки на узком экране — редактор и вывод в столбец, а не рядом.

**Доступность.** `aria` есть только у поиска. Табы разметить как `tablist`,
спойлеры сделать `<button aria-expanded>`, лайтбоксу — ловушку фокуса
и возврат фокуса на миниатюру, добавить skip-link и `prefers-reduced-motion`.

**Офлайн.** Service worker + манифест: контент статический, ложится в кеш
целиком, включая Pyodide. Ученик в дороге открывает справочник без сети.

**Мелочи.** `@media print` для печати шпаргалок; `description`, Open Graph
и favicon в `<head>` (сейчас ссылка в мессенджере разворачивается пустой);
`youtube-nocookie` вместо `youtube.com` во встраивании видео.
